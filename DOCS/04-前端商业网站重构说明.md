# 前端商业网站重构说明

## 0. 结论：这是重构，不是润色

当前前端的主要问题不是按钮、字体或动画，而是它向用户出售了错误的产品：

```text
当前：场景沉浸式口语陪练
目标：从短视频画面发起的视觉词汇搜索与记忆产品
```

因此，不应在旧的“进入角色 → 开口说 → AI 纠正”叙事上继续优化；应保留可复用的视频播放器和帧识别能力，重写商业首页、应用主流程和词库页面。

## 1. 前端的唯一任务

让第一次来到网站的人，在 20 秒内理解以下三件事：

1. 我正在刷的视频，就是学习素材。
2. 我不必先知道关键词；暂停一帧就能搜到画面表达。
3. 我不会的表达会变成带画面语境、之后还能复习的个人帧词卡。

## 2. 不可违背的产品故事

```text
看见却不会说
  → 暂停这一帧
  → AI 找到适合我水平的表达
  → 收进帧词库
  → 之后看着这段画面想起来
```

禁止把以下内容作为首屏、主 CTA 或 Demo 主线：

- 角色扮演、进入场景、模拟点单。
- 开口说、语音录制、语音评分、实时教练。
- “沟通完成度”“更自然的说法”。

这些能力如果将来保留，只能放在词条详情的次级扩展，不得抢占视觉搜索和记忆的主叙事。

## 3. 信息架构与路由

```text
/             商业首页：为什么现在就想打开
/app          视觉搜索器：完成一次真实帧级识别
/library      帧词库：查看和复习个人记忆
/demo         评委演示：60–90 秒可控闭环
/how-it-works 项目/技术说明：给评委和合作方
```

顶部导航固定为：

```text
这一帧怎么说 | 如何工作 | 帧词库 | 体验一下
```

不要出现“演示 / 应用”这种开发者视角命名；用户只需要知道“如何工作、我的词库、开始体验”。

## 4. 首页 `/`：商业叙事分镜

首页是品牌入口，不是功能说明书。视觉方向可借鉴 Shopify Editions 的沉浸感、编辑化章节和密集信息组织，但不得复制其文案、插画、素材或布局。

### 4.1 首屏：英语从正在看的世界里出现

**用户问题**：为什么我会停下来？

**画面**：全屏真实视频/画面拼贴；单词以有深度的浮层穿过画面。单词必须是产品真实会识别的表达，而不是无意义装饰。

```text
steam      aisle      drizzle      simmer
bustling   layover    pour         checkout
```

**主标题**：

> 每一帧，都有你还没学会的说法。

**副标题**：

> 暂停短视频，AI 看懂画面，把你看见却不会说的表达收进词库。

**主 CTA**：`上传视频，搜索这一帧`

**次 CTA**：`看 60 秒演示`

**可信度提示**：`视频留在设备中 · 仅暂停帧用于识别`

### 4.2 第二屏：用户不需要知道怎么搜

**用户问题**：我为什么不用普通搜索？

左侧为一段短视频的暂停画面，右侧为用户内心独白：

> “他正在做的这个动作，英语到底怎么说？”

滚动后，画面中自然出现 3 个标签：

```text
steam the milk · B1
pour steadily · B1
coffee machine · A2
```

**结论文案**：

> 你不用先想好关键词。看见、暂停，就够了。

### 4.3 第三屏：同一帧，因你而不同

**用户问题**：为什么我不会被塞一堆简单词？

同一张画面使用切换控件展示三个等级的推荐：

| 等级 | 推荐示例 |
| --- | --- |
| A1–A2 | cup / chair / street |
| B1–B2 | pour steadily / place an order |
| C1–C2 | froth the milk / counter service |

**标题**：

> 不是更多单词，是刚好比你现在多一步。

### 4.4 第四屏：把这一帧收进词库

**用户问题**：识别完之后，为什么值得留下？

展示一张帧词卡，必须包含：

- 这段视频的截图或画面裁切；
- 目标词；
- 中文释义；
- 画面例句；
- 来源场景与学习等级；
- `加入帧词库` 的明确动作。

**标题**：

> 不是收藏一个词，是带走你亲眼见过的那一刻。

### 4.5 第五屏：重播与记忆

**用户问题**：为什么这件事会发生在短视频里，而不是背词 App？

展示同一视频时间轴：第一次暂停识别；用户回退几秒重看动作；之后在词库中看到这段画面。

**标题**：

> 一个词，让你愿意再看一遍这一帧。

**说明**：

> 当词和画面绑在一起，短视频不再只是划过去的内容，而是你可以重新理解的记忆线索。

注意：这是产品假设和体验价值，不要写成“已提升 X% 重播率”。

### 4.6 第六屏：复习不是另一套产品

**用户问题**：我以后如何记住？

展示最小复习卡：先显示被遮住的词与原画面，用户点击 `认识` 或 `再看看`。

**标题**：

> 以后再见到它，你会知道怎么说。

**收尾 CTA**：`从你正在看的视频开始`

## 5. 应用页 `/app`：视觉搜索器

应用页只服务于一次成功的搜索，不承担所有产品叙事。

### 页面结构

```text
顶部：品牌 / 当前语言 / 当前难度 / 我的帧词库
中部：视频画面与“暂停识别”主操作
画面层：学习点标签
底部：当前帧摘要、重新识别、继续播放
右侧/底部抽屉：词条详情
```

### 必须存在的状态

| 状态 | 用户看见什么 | 主操作 |
| --- | --- | --- |
| 初始 | 上传视频、示例视频、隐私提示 | 上传视频 |
| 播放中 | “暂停这一帧，找出你不会说的表达” | 暂停识别 |
| 分析中 | 当前帧不消失；清楚说明 AI 正在寻找什么 | 等待 / 取消 |
| 结果 | 3–5 个不重叠的词汇标签 | 点开词条 |
| 空结果 | “这一帧没有值得新增的表达，换一帧试试” | 继续播放 |
| 失败 | 不暴露技术错误；提供“重新识别” | 重试 |
| 已收藏 | 词条卡显示“已在帧词库” | 打开词库 |

### 词条详情抽屉

信息层级严格如下：

1. `steam the milk`（目标语言表达）
2. `给牛奶打蒸汽`（中文释义）
3. `B1 · 动作 · 来自咖啡馆画面`
4. 画面例句与翻译
5. 三个常用搭配
6. 主按钮：`加入帧词库`
7. 次按钮：`不想再看到`

不要把“朗读、角色任务、语音挑战”放入首屏可见区域。

## 6. 帧词库 `/library`：从一次性功能变成产品

### 首次进入

```text
你还没有帧词卡。
从一段视频里暂停一帧，收下第一个“看见却不会说”的表达。
[去搜索这一帧]
```

### 有数据时

顶部只显示三个最重要的信息：

```text
今日待复习 3 个 | 已收集 18 个表达 | 来自 6 段视频
```

下方用场景化卡片而非纯词表：

```text
[咖啡馆截图] steam the milk · B1 · 待复习
[街头截图] bustling · B2 · 已认识 1 次
```

### 复习模式

```text
原画面 + 场景提示
“咖啡师正在处理牛奶。”
你还记得这个表达吗？
[认识] [再看看]
```

不要求用户输入、朗读或拼写，先降低碎片化复习的阻力。

## 7. 评委 Demo 页 `/demo`

这不是营销首页，也不需要登录。它必须稳定地展示唯一闭环：

```text
暂停真实画面
→ AI 标出表达
→ 收藏为帧词卡
→ 打开词库
→ 完成一次复习
```

建议使用预置场景和可控演示数据，但页面必须明确标注“真实应用可上传任意视频”。

## 8. 视觉系统方向

### 应该有的气质

- 像一本不断被短视频写出来的动态英语杂志，而不是在线教育后台。
- 强烈的画面感、单词的空间感、清晰的编辑化文字层级。
- 深色/自然视频底色与高对比浅色文字；单词标签使用克制但有区分度的色彩。
- 动画服务于“词从画面被找出来”，而不是无目的炫技。

### 不应该有的气质

- 通用 AI SaaS 的渐变卡片、三栏功能区、发光机器人。
- 大量“AI 教练”“实时反馈”“任务完成度”的教育产品语气。
- 把每项能力做成同权重卡片，导致用户不知道下一步做什么。

## 9. 组件清单

```text
WordFieldHero           首页沉浸式单词场
FrameSearchPlayer       视频播放器与暂停取帧
LearningTag             帧内词汇标签
LevelLens               CEFR 难度切换演示
WordDetailSheet         词条详情抽屉
SaveToLibraryButton     入库动作与状态
FrameWordCard           带截图的帧词卡
ReviewCard              认识 / 再看看
ReplayTimeline          同视频回看与记忆关系说明
```

## 10. 前端验收标准

以下全部满足，前端才算完成，而不是“页面看起来不错”：

1. 首次用户 20 秒内能复述“暂停视频可以搜英语表达”。
2. 用户不会把产品误认为口语陪练或翻译工具。
3. 从首页 CTA 到 `/app` 的路径只有一个明确目标：暂停并识别。
4. 应用页可完成真实 `暂停 → 识别 → 详情 → 收藏`。
5. 词库页可看到刚收藏的词，并能完成 `认识 / 再看看`。
6. Demo 页不依赖现场麦克风、实时语音或复杂登录。
7. 任何加载、空结果、网络失败、首次空词库都有可理解的文案与下一步。
8. 桌面与手机均把“视频画面”和“当前主操作”放在第一视觉层级。

## 11. 实施顺序

1. 先删旧口语叙事，替换导航和 CTA 文案。
2. 完成 `/library` 与 `ReviewCard`，让“记住”有真实界面。
3. 改 `/app` 的主动作和词条详情，接入收藏状态。
4. 用真实能力和已写好的商业故事重做首页章节。
5. 最后做单词场、滚动动效、细节动画和截图素材。

**原则：先让页面证明产品闭环，再让页面变得惊艳。**
